# WeChatMsgArchive 数据更新与维护策略

## 1. 更新策略总览

微信数据具有持续产生、动态变化的特点。本策略定义如何从持续运行的微信客户端中高效、安全地更新分析数据。

```
更新频率决策树:

数据时效性要求
    ├── 实时监控 (分钟级) ──→ 内存直读 + 增量分析
    ├── 日常追踪 (小时级) ──→ 定时任务 + 增量提取
    ├── 周报/月报 (天级)  ──→ 每周全量刷新
    └── 归档分析 (月/季级) ──→ 手动触发全量重建
```

---

## 2. 增量更新机制

### 2.1 核心思想

增量更新基于**时间戳水印**，只处理上次更新后新增/变更的数据。

```python
# 水印存储格式 (watermark.json)
{
  "last_extract_time": 1714204800,  # 上次提取的最大时间戳
  "last_extract_ids": [12345, 12346], # 已提取的 server_id 列表（可选）
  "version": "v3",
  "wxid": "wxid_xxxxxxxx",
  "updated_at": "2024-04-27T10:00:00"
}
```

### 2.2 增量提取流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 读取水印文件 │ --> │ 查询 MSG 表  │ --> │ 提取新消息  │
│ watermark   │     │ WHERE       │     │ (timestamp  │
│ .json       │     │ CreateTime >│     │  > watermark)│
└─────────────┘     │ watermark   │     └─────────────┘
                    └─────────────┘            ↓
                                        ┌─────────────┐
                                        │ 更新水印    │
                                        │ 保存新时间戳│
                                        └─────────────┘
```

### 2.3 增量提取代码示例

```python
# data_extractor.py 增量模式调用
extractor = create_extractor('v3', db_dir, output_dir)
extractor.init_db()

# 读取上次水印
watermark = load_watermark()
last_time = watermark.get('last_extract_time', 0)

# 增量提取
new_count = extractor.extract_messages(
    talker_ids=None,
    incremental_after=last_time
)

# 更新水印
new_watermark = {
    'last_extract_time': int(time.time()),
    'version': 'v3',
    'updated_at': datetime.now().isoformat()
}
save_watermark(new_watermark)
```

### 2.4 增量清洗

清洗阶段也支持增量：

```sql
-- 只清洗新提取的消息
INSERT INTO messages_clean 
SELECT * FROM messages 
WHERE timestamp > ? 
  AND server_id NOT IN (SELECT server_id FROM messages_clean);
```

## 3. 定时任务方案

### 3.1 Windows 任务计划程序

创建 `.bat` 批处理文件：

```batch
@echo off
chcp 65001 >nul
cd /d D:\develoment_home\project_home\WeChatMsgArchive

call venv\Scripts\activate.bat

python data_analysis/scripts/auto_update.py ^
    --version v3 ^
    --db-dir output/decrypted_db ^
    --output-dir data_analysis/output ^
    --mode incremental

deactivate
```

使用 `schtasks` 创建定时任务：

```cmd
schtasks /create /tn "WeChatDataUpdate" ^
  /tr "D:\...\auto_update.bat" ^
  /sc hourly /st 09:00 ^
  /et 18:00 /k
```

### 3.2 Python 定时脚本

```python
# auto_update.py
import schedule
import time

def job():
    # 检查微信是否运行
    if not is_wechat_running():
        logger.info("微信未运行，跳过本次更新")
        return
    
    # 1. 解密（如需要）
    # 2. 增量提取
    # 3. 增量清洗
    # 4. 增量分析
    # 5. 导出更新
    run_pipeline(mode='incremental')

schedule.every(1).hours.do(job)

while True:
    schedule.run_pending()
    time.sleep(60)
```

## 4. 数据版本管理

### 4.1 数据库快照

定期进行全量快照，便于回溯对比：

```python
def create_snapshot(base_db: str, snapshot_dir: str):
    timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
    snapshot_path = f"{snapshot_dir}/snapshot_{timestamp}.db"
    
    # SQLite 备份
    import shutil
    shutil.copy2(base_db, snapshot_path)
    
    # 同时保存元数据
    meta = {
        'timestamp': timestamp,
        'source_db': base_db,
        'record_count': get_record_count(base_db)
    }
    with open(f"{snapshot_path}.meta.json", 'w') as f:
        json.dump(meta, f)
```

### 4.2 快照保留策略

| 快照类型 | 频率 | 保留数量 |
|---------|------|---------|
| 每小时 | 1小时 | 最近 24 个 |
| 每日 | 1天 | 最近 7 个 |
| 每周 | 1周 | 最近 4 个 |
| 每月 | 1月 | 最近 12 个 |

```python
def cleanup_old_snapshots(snapshot_dir: str):
    """清理过期快照，保留策略如上"""
    snapshots = sorted(Path(snapshot_dir).glob('snapshot_*.db'))
    # 保留最近 N 个，删除其余
    for old in snapshots[:-KEEP_COUNT]:
        old.unlink()
        meta = old.with_suffix('.db.meta.json')
        if meta.exists():
            meta.unlink()
```

## 5. 数据一致性保障

### 5.1 去重机制

消息表以 `server_id` 为主键，`INSERT OR IGNORE` 确保重复数据不会进入：

```sql
INSERT OR IGNORE INTO messages (server_id, ...)
VALUES (?, ...)
```

### 5.2 联系人信息更新

联系人信息（如昵称、备注）可能变更，更新策略：

```sql
-- 使用 REPLACE，以最新数据为准
INSERT OR REPLACE INTO contacts (wxid, remark, nickname, ...)
VALUES (?, ?, ?, ...)
```

### 5.3 群成员变更追踪

群成员有加入/退出，建议记录变更历史：

```sql
CREATE TABLE chatroom_member_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chatroom_id TEXT,
    wxid TEXT,
    event_type TEXT,  -- 'join', 'leave', 'display_name_change'
    event_time TEXT,
    old_value TEXT,
    new_value TEXT
);
```

## 6. 存储空间管理

### 6.1 空间估算

| 数据项 | 单条大小 | 10万条约占 | 100万条约占 |
|--------|---------|-----------|------------|
| 消息记录 | ~500B | ~50 MB | ~500 MB |
| 联系人 | ~2KB | ~2 MB | ~20 MB |
| 清洗后数据 | ~300B | ~30 MB | ~300 MB |
| 分析结果 JSON | - | ~5 MB | ~50 MB |
| **总计** | - | **~90 MB** | **~900 MB** |

### 6.2 清理策略

```python
def cleanup_old_data(db_path: str, keep_days: int = 365):
    """清理超过保留期限的原始消息，但保留统计摘要"""
    cutoff = int((datetime.now() - timedelta(days=keep_days)).timestamp())
    
    conn = sqlite3.connect(db_path)
    
    # 1. 将旧数据归档到月汇总表
    conn.execute("""
        INSERT INTO monthly_summary 
        SELECT 
            strftime('%Y-%m', datetime(timestamp, 'unixepoch')) as month,
            talker_id,
            sender_id,
            msg_type,
            COUNT(*),
            SUM(content_length)
        FROM messages_clean
        WHERE timestamp < ?
        GROUP BY month, talker_id, sender_id, msg_type
    """, (cutoff,))
    
    # 2. 删除原始旧消息
    conn.execute("DELETE FROM messages_clean WHERE timestamp < ?", (cutoff,))
    conn.commit()
    conn.close()
```

## 7. 备份与恢复

### 7.1 备份清单

| 备份项 | 路径 | 优先级 |
|--------|------|--------|
| 解密后的数据库 | `output/decrypted_db/` | 高 |
| 清洗后数据库 | `data_analysis/output/cleaned_data.db` | 高 |
| 分析结果 JSON | `data_analysis/output/*.json` | 中 |
| 生成的 Markdown | `data_analysis/output/*.md` | 低（可重新生成） |
| 水印文件 | `data_analysis/output/watermark.json` | 高 |

### 7.2 自动备份脚本

```python
import shutil
from datetime import datetime

def backup_analysis_data():
    src_dirs = [
        'output/decrypted_db',
        'data_analysis/output'
    ]
    
    backup_base = f"backup/{datetime.now().strftime('%Y%m%d')}"
    
    for src in src_dirs:
        dst = f"{backup_base}/{Path(src).name}"
        shutil.copytree(src, dst, dirs_exist_ok=True)
    
    print(f"备份完成: {backup_base}")
```

## 8. 监控与告警

### 8.1 关键指标监控

```python
MONITORING_METRICS = {
    'last_update_time': '上次成功更新时间',
    'messages_per_hour': '每小时新增消息数',

    'db_size_mb': '数据库大小',
    'duplicate_ratio': '去重比例（异常高可能代表问题）',

```

### 8.2 异常告警条件

| 条件 | 级别 | 处理建议 |
|------|------|---------|
| 超过 4 小时无新消息 | 警告 | 检查微信是否运行 |
| 去重比例 > 50% | 警告 | 检查时间戳或提取逻辑 |
| 数据库大小单日增长 > 500MB | 警告 | 检查是否有大文件消息 |
| 提取成功率 < 90% | 严重 | 检查数据库完整性 |
| 解密失败 | 严重 | 重启微信或检查密钥 |

## 9. 灾难恢复流程

```
场景: 数据库损坏或数据丢失

1. 停止所有定时任务
2. 从备份恢复解密数据库
3. 重新运行全量提取（data_extractor）
4. 重新运行全量清洗（data_cleaner）
5. 重新运行分析（profile_builder）
6. 重新导出 Markdown
7. 重置水印为最新时间
8. 恢复定时任务
```
