# WeChatMsgArchive 数据字典

## 1. 概述

本文档定义 WeChatMsgArchive 项目数据分析所需的全部数据源、表结构、字段映射及清洗规则。

项目支持微信 v3 (3.9.x) 和 v4 (4.0.x) 两个数据库版本，以下分别说明。

---

## 2. 数据源总览

| 数据库文件 | 版本 | 核心用途 | 对应分析维度 |
|-----------|------|---------|-------------|
| MSG*.db (v3) / message.db (v4) | 双版本 | 消息内容、时间、类型 | 聊天记录、用户行为、时间序列 |
| MicroMsg.db (v3) / contact.db (v4) | 双版本 | 联系人、群聊、标签 | 用户画像、关系图谱、成员分析 |
| MediaMSG*.db (v3) / media.db (v4) | 双版本 | 语音数据 | 语音转文字、多媒体分析 |
| HardLinkImage.db / HardLinkVideo.db / HardLinkFile.db | 双版本 | 文件路径映射 | 多媒体资源定位 |
| Sns.db (v3) | v3 | 朋友圈数据 | 社交活跃度、内容分析 |
| Session.db (v3) / session.db (v4) | 双版本 | 会话列表、未读数 | 活跃度、优先级排序 |

## 3. 字段详细映射

### 3.1 消息表 (MSG / Msg_<md5>)

#### v3 字段映射

| 原始字段 | 标准字段名 | 数据类型 | 说明 | 清洗规则 |
|---------|-----------|---------|------|---------|
| `localId` | `local_id` | INT | 本地自增消息ID | 保留原值 |
| `MsgSvrID` | `server_id` | INT | 服务器消息唯一ID | 保留原值，用于去重 |
| `Sequence` | `sort_seq` | INT | 排序序列号（CreateTime + 3位递增） | 保留原值 |
| `CreateTime` | `timestamp` | INT | 秒级 Unix 时间戳 | 转换为 `YYYY-MM-DD HH:MM:SS` |
| `Type` + `SubType` | `msg_type` | ENUM | 消息类型 | 映射到标准 MessageType |
| `StrTalker` | `talker_id` | TEXT | 聊天对象 wxid | 群聊以 `@chatroom` 结尾 |
| `IsSender` | `is_sender` | BOOL | 是否自己发送 | 1=True, 0=False |
| `StrContent` | `content` | TEXT | 文本内容或 XML | XML 需进一步解析 |
| `CompressContent` | `compress_content` | BLOB | lz4 压缩数据 | 解压后提取结构化信息 |
| `BytesExtra` | `bytes_extra` | BLOB | protobuf 附加数据 | 解析获取群聊发送者 wxid |
| `DisplayContent` | `display_content` | TEXT | 界面显示文本 | 用于通话、系统消息 |
| `Status` | `status` | INT | 消息状态 | 保留原值 |

| 原始字段 | 标准字段名 | 数据类型 | 说明 | 清洗规则 |

| `server_id` | `server_id` | INT | 服务器消息ID | 保留原值 |

### 4.2 ContactType 位掩码解析

```python
class ContactType:
    Sticky   = 1 << 0   # 1   - 置顶
    Star     = 1 << 1   # 2   - 星标好友
    Chatroom = 1 << 2   # 4   - 群聊
    Normal   = 1 << 3   # 8   - 普通联系人
    Stranger = 1 << 4   # 16  - 陌生人
    OpenIM   = 1 << 5   # 32  - 企业微信
    Public   = 1 << 6   # 64  - 公众号
    Unknown  = 1 << 8   # 256 - 已解散/退出的群
```

使用位运算判断类型：
- `type & 4 != 0` → 群聊
- `type & 8 != 0` → 普通联系人
- `type & 64 != 0` → 公众号

## 5. 派生字段定义

在原始字段基础上，数据分析需要计算的派生字段：

| 派生字段名 | 计算方式 | 用途 |
|-----------|---------|------|
| `display_name` | 优先 remark → nickname → wxid | 统一展示名称 |
| `sender_name` | 根据 sender_id 查询联系人表 | 消息发送者展示名 |
| `date` | `datetime.fromtimestamp(timestamp).date()` | 按天聚合 |
| `hour` | `datetime.fromtimestamp(timestamp).hour` | 时段分析 |
| `weekday` | `datetime.fromtimestamp(timestamp).weekday()` | 周内行为模式 |
| `message_length` | `len(content)` (仅文本类消息) | 发言长度分析 |
| `is_work_hours` | `9 <= hour <= 18` | 工作/生活时间区分 |
| `is_weekend` | `weekday in [5, 6]` | 周末行为分析 |
| `reply_to` | 解析 Quote 消息的引用 server_id | 回复关系链 |
| `domain` | 从 LinkMessage 提取域名 | 内容来源分析 |
| `file_extension` | 从 FileMessage 提取后缀 | 文件类型统计 |
| `emotion_score` | 情感分析模型输出 | 情绪趋势 |

## 6. 数据质量规则

### 6.1 必填字段校验

- `server_id`: 必须存在且 > 0（用于去重）
- `timestamp`: 必须存在且在合理范围内 (2010-01-01 至 当前时间)
- `talker_id`: 必须存在且符合 wxid 格式
- `msg_type`: 必须可映射到已知类型，未知类型标记为 `Unknown`

### 6.2 异常数据处理

| 异常场景 | 处理策略 |
|---------|---------|
| 时间戳为 0 或未来时间 | 标记为 `invalid_timestamp`，使用 `sort_seq` 推算 |
| content 为 None 或空字符串 | 根据类型填充默认值，如 Image → "[图片]" |
| 发送者无法解析 | 标记为 `unknown_sender`，使用 `wxid_unknown_{hash}` |
| 重复 server_id | 保留第一条，后续记录写入 `duplicate_log` |
| XML 解析失败 | 保留原始字符串，标记 `xml_parse_error=True` |
| 压缩内容解压失败 | 标记 `decompress_error=True`，跳过结构化提取 |

### 6.3 隐私脱敏规则

| 敏感信息 | 脱敏策略 |
|---------|---------|
| 手机号 | 保留前3位和后4位，中间用 `****` 替代 |
| 微信号 (alias) | 完全保留（公开标识）或按需求脱敏 |
| wxid | 内部使用原值，输出时映射为匿名ID |
| 精确位置坐标 | 保留到小数点后2位（约1km精度） |
| 转账金额 | 输出时模糊化为区间（如 0-100元） |

## 7. 版本兼容性对照

### 7.1 SQL 查询差异

```python
# v3 查询消息
v3_sql = """
    SELECT localId, MsgSvrID, Sequence, CreateTime, Type, SubType,
           IsSender, StrTalker, StrContent, CompressContent, BytesExtra, Status
    FROM MSG
    WHERE StrTalker = ?
    ORDER BY Sequence
"""

# v4 查询消息
v4_sql = """
    SELECT local_id, server_id, sort_seq, create_time, local_type, 0 as sub_type,
           CASE WHEN real_sender_id = ? THEN 1 ELSE 0 END as is_sender,
           origin_source as talker_id, message_content as content,
           compress_content, packed_info_data, status
    FROM Msg_{md5(talker_id)}
    ORDER BY sort_seq
"""
```

### 7.2 发送者解析差异

```python
# v3: 从 BytesExtra (protobuf) 解析
if not is_sender:
    sender_id = parse_bytes_extra_v3(bytes_extra)

# v4: 从 message_content 前缀解析 或 real_sender_id
if is_chatroom:
    # message_content 格式: "wxid_xxx:实际内容"
    sender_id, content = parse_content_prefix_v4(message_content)
else:
    sender_id = talker_id
```

## 8. 索引建议

为提升分析查询效率，建议在中间数据库创建以下索引：

```sql
-- 消息核心索引
CREATE INDEX idx_msg_talker_time ON messages(talker_id, timestamp);
CREATE INDEX idx_msg_sender ON messages(sender_id, timestamp);
CREATE INDEX idx_msg_type ON messages(msg_type, timestamp);
CREATE INDEX idx_msg_date ON messages(date);

-- 联系人索引
CREATE INDEX idx_contact_type ON contacts(contact_type);
CREATE INDEX idx_contact_label ON contacts(label_name);

-- 群成员索引
CREATE INDEX idx_member_chatroom ON chatroom_members(chatroom_id, wxid);
CREATE INDEX idx_member_join_time ON chatroom_members(join_time);
```
