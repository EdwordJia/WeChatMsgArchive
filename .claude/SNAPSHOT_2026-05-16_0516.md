## 经验沉淀（追加）

### 沿用
- 用 regex.search(pattern, src, re.DOTALL) 定位锚点 + 字符串切片替换 = 最可靠的 surgical patch 方式
- 每次改完立即 `python -c "import ast; ast.parse(...)"` 验证
- 状态文件用 JSON in `.claude/state/`，便于跨 cron 运行持久化

### 不要再做
- 不要尝试用 Edit 工具替换跨多个空行的代码块（容易 string-not-found）
- 不要直接重写 stub 方法不经过 ast.parse 验证

### 通用模式
- "新建模块 + try/except import 兜底升级" 是改 stub 的最低风险路径
- 入队（队列文件）+ 桥接（cron 触发 Claude 处理）= 可控的自动化
