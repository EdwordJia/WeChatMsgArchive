## 经验教训（追加）

### 工具 vs Python
- bash heredoc / Write 工具 / Edit 工具对深嵌套 Python（4-20 空格混合）会损坏缩进
- 唯一可靠路径：用 `'    ' * level` 函数显式生成缩进，让 Python 自己写 .py 文件

### 调试方法
- pipeline 跑通后 `print(p.pending_tasks)` 看具体识别内容比看 stage 计数有用得多
- ChatRoom UserNameList 用 `repr(value[:100])` 看字面字符比相信 memory 描述靠谱

### 决策模式
- 不动旧 fetcher，新建 v2 模块 + try/except import 是最低风险路径
- 同样思路适用 Stage 3/5：不改 stub 函数，新建一个独立的 task_landing.py 处理 MCP 落地
