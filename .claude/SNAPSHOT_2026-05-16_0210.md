## 本轮经验教训

### 失败模式（避免）
1. **bash heredoc 写复杂 Python 易损坏缩进** — 我多次尝试用 `cat << 'EOF'` 写 fetcher 修复版，每次都因为某些特定字符组合导致缩进被规范化掉。**结论**：复杂 Python 一律用 Write 工具或委派子 agent。
2. **重复创建项目** — 没先查现有项目就建了 `ai-legal-doc-assistant`，结果发现 `ai-zs` 已经存在对应同一微信群。**结论**：动手前先 `list_projects` + 看 memory/project_mapping.md。
3. **不要 fight 工具** — 同一个任务连续失败 2 次后立刻换路径（委派子 agent / 用不同工具 / 写 task 接力）。

### 成功模式（沿用）
1. **委派子 agent 处理脏活** — Explore/general-purpose agent 拿到完整 context 一次性产出 224KB 消息文件 + 15KB 需求文档。
2. **批量并行 create_task** — 一次性 4-10 个 task 落地，效率高。
3. **memory 即时更新** — project_mapping.md 立刻同步新增字段，下一轮直接可用。
