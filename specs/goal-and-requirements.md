# 个人微信消息归档与分析工作站

## 目标与问题

微信把用户的聊天历史锁在本机加密 SQLite 数据库里，官方不提供导出与检索能力。本项目（WeChatMsg「留痕」的定制分叉，代号 WeChatMsgArchive）让**个人用户留存、检索、分析自己的消息数据**：从运行中的微信进程提取密钥、解密数据库，进而导出、监控、挖掘其中的价值。

延续上游前言的原则：**「我的数据我做主」——仅面向本人数据的留存与分析**。

## 用户与运行形态

- 单一用户：本机微信账号持有者本人，非多用户产品。
- 运行形态：Windows 本机脚本/计划任务运行；依赖微信客户端进程在线以提取解密密钥。

## 能力

1. **数据库解密**：从运行中的微信进程内存提取密钥，AES 解密微信 v3 / v4 的本地 SQLite 数据库（联系人、消息、媒体、语音等），落盘为明文库。
2. **同步与导出**：一键完成「解密 → 遍历 MSG 库 → 导出指定群聊/联系人 → 生成报告」；导出支持 HTML、CSV、DOCX、TXT、JSON、Markdown、XLSX、AI 友好文本等多种格式。
3. **实时监控**：文件系统监听解密库变化，秒级增量捕获新消息，替代定时轮询。
4. **数据流水线**：v3/v4 双版本数据抽取、清洗（去重/时间戳校验/内容清洗）、基于时间戳水印的增量更新、统一数据模型、Markdown 分析报告生成。
5. **分析洞察**：用户画像、关系图谱（社交共现网络）、副业项目追踪、商机识别、消息串线（会话线程还原）。
6. **LLM 辅助分析**：接入 DeepSeek / Claude / 本地模型做语义级需求收集与自动分析流水线，产出同步到看板（kanban）任务。
7. **标准化数据接口**：MCP 服务向 AI 工具暴露标准化的消息/联系人查询接口。
8. **多平台扩展架构**（长期演进方向）：PlatformAdapter 适配器层统一微信/飞书/企业微信数据模型，已实现、待主流程接入。
9. **本地 AI 聊天**：保留上游 MemoAI 组件（本地 Qwen 模型问答）。

## 非目标

- **维护上游 GUI 应用**：上游「留痕」GUI 不再是本工作区的维护目标（经用户确认；`app/` 目录已不存在）。
- **数据恢复与篡改**：不恢复已删除的聊天记录，不提供任何修改微信原始数据的能力（延续上游声明）。
- **多用户 / 服务端部署**：不做多租户、不做网络服务化。
- **非法用途**：任何超出「本人数据」范围的用途均不在目标内。

## 原则

- 明文数据仅落盘本机 `output/` 目录，不外传（LLM 调用除外，由配置显式控制）。
- 新分析功能优先复用标准数据层与导出器，不 proliferate 一次性脚本（根目录历史脚本见 architecture 的边界说明）。
